# Границы компонентов

Предполагаемый поток данных:

1. Администратор создаёт проект и загружает медиа через CMS.
2. CMS проверяет права доступа и файлы, сохраняет контент и ссылки на медиа.
3. Публичный сайт получает опубликованные данные через API.
4. Медиа отдаётся из выбранного хранилища; локально возможен `storage/uploads/`.

Отдельный `backend/` нужен только для функций, которых не хватает CMS.
Выбор CMS, фреймворка, базы данных, хранилища и хостинга ещё не сделан.
Каталоги являются местами для будущей реализации, а не работающими сервисами.

Исходные материалы в `references/` остаются локальными. В репозиторий попадают
только подготовленные для публикации ресурсы и безопасные тестовые примеры.
